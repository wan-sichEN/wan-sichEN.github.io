Haptic Paddle

Created a 1 DOF haptic joystick that renders virtual forces to the user's hand.

Year: 2026 Status: Complete

Overview

For the final project of ME433: Advanced Mechatronics, I was tasked with making a custom “haptic paddle” using our own 3D-printed parts and given electronics (Fig. 1).

The goal was to have the haptic paddle react to a virtual environment and resist the user’s movement when walking in more viscous terrain (e.g., water).

Fig. 1: Haptic paddle demo

Circuit Design

We were given the following electronics:

  • Raspberry Pi Pico 2W
  • STM32 NUCLEO-C092RC
  • MCP2562 CAN Transceiver Chip
  • Deconstructed Servo Motor
  • DRV8833 H-Bridge Motor Driver
  • Load Cell & HX711 Amplifier Board
  • INA219 Current Sensor
  • AS5600 Magnetic Encoder

Fig. 2: Circuit diagram

The STM32 runs motor control using the current sensor, servo motor, and H-bridge, while the Pico 2W handles force feedback using the load cell and encoder. The Pico computes the desired motor current based on the virtual environment and sends it to the STM32 over CAN bus, chosen for its reliability and noise resistance. See Fig. 2 for the circuit diagram.

Joystick Design

Using Onshape and 3D-print prototyping, I designed the motor housing, arm, and ergonomic handle which make up the mechanical joystick (Fig. 3, 4, 5, 6).

The arm has a square section that uses two 4-40 screws to clamp onto the edges of the load cell. The handle bottom then clamps onto the center of the load cell so that a force on the handle bends the load cell and it picks up the reading.

Haptic Control

I implemented haptic feedback using the closed-loop pipeline below (Fig. 7):

  1. The Pico continuously reads the joystick angle (AS5600 encoder) and streams it to the computer over USB serial.
  2. The computer updates Python terrain graphics based on angle.
  3. The Pico reads force (HX711) and computes a desired force based on terrain location (Fig. 8) and movement direction (computed via encoder). In grass, desired force matches the measured baseline (zero haptic feedback). In water, desired force increases with depth and resists movement direction.
  4. The Pico runs PD control on the force error and converts the output to a desired current value.
  5. The desired current is sent to the STM32 over CAN bus.
  6. The STM32 runs PI current control, reading actual current via INA219 and adjusting motor PWM accordingly.

See the code implementation on GitHub.

In practice, the AS5600 encoder produced very jittery readings that made the joystick appear to shake even when stationary. To address this, I implemented a digital low-pass filter: avg_position = 0.1*new_position + 0.9*prev_avg_position, which weights new positions less to attenuate high frequency noise while still preserving low frequency changes that reflect actual movement. However, overweighting the previous average causes lag that impairs haptic response, so the coefficients were empirically tuned to balance the two.

Additionally, the load cell readings would drift, making it appear as though force was already applied to the joystick when it was simply the baseline force shifting. To address this, I implemented a dynamic recalibration algorithm that continuously averages force readings while the joystick is stationary and updates the baseline accordingly.

Finally, the PID controllers used for force and current control required extensive tuning. High proportional gain was necessary for strong and immediate haptic feedback, but also caused instability and sharp overshoots. Adding integral gain introduced integrator windup, causing the motor to drift without user input. Generally, higher gains amplified noise and haptic asymmetry (motor instability in one direction but not the other). After delicately balancing all three gains, I achieved satisfactory resistive feedback in the water region and a stable grass-to-water transition, though the resistive strength in the deep water region appears to be limited by current saturation.
